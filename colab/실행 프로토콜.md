# Colab 학습 실행 프로토콜

노트북 하나로 세 단계를 돕니다. 위 셀의 스위치만 바꾸면 됩니다.


앞 단계를 건너뛰지 마세요. 15시간짜리 학습을 검증 없이 시작하면 끊겼을 때 처음부터입니다.

만든 `drone_hackathon` 폴더를 더블클릭해서 들어간 다음, 같은 방법으로 그 안에

### 1-2. 노트북 열기

### 1-3. GPU 켜기

노트북이 열린 상태에서 위쪽 메뉴의 런타임 > 런타임 유형 변경 을 누릅니다.

"하드웨어 가속기" 에서 L4 GPU 를 고르고 저장을 누릅니다.

같은 창에 "백그라운드 실행" 항목이 있으면 켜세요. 요금제에 따라 없을 수도
있는데, 없어도 학습은 됩니다. 대신 노트북 탭을 닫지 마세요. 닫으면 세션이
끊길 수 있습니다. (끊겨도 체크포인트에서 이어지긴 합니다. 그걸 확인하는 게
바로 아래 1-5입니다.)

A100은 고르지 마세요. YOLO11n은 파라미터가 3.2M밖에 안 되는 가벼운 모델이라
1280 해상도에서도 병목이 GPU 연산이 아니라 이미지를 읽고 푸는 쪽입니다.
A100으로 바꿔도 그만큼 빨라지지 않는데 CU는 2배 넘게 씁니다. Pro의 100 CU로
R9와 R10을 둘 다 돌려야 합니다.

### 1-4. 자체 점검 실행

첫 번째 코드 셀에 이렇게 되어 있는지 확인합니다.

```python
SELFTEST = True
SMOKE    = False
```

그다음 메뉴에서 런타임 > 모두 실행 을 누릅니다. (단축키 Ctrl+F9)

진행하면서 아래 세 가지가 나옵니다. 순서대로 처리하세요.

경고창 "이 노트북은 Google에서 작성하지 않았습니다"

- 내가 올린 파일이라 나오는 안내입니다. "무시하고 계속하기" 를 누릅니다.

팝업 "이 노트북에서 Google Drive 파일에 액세스하도록 허용하시겠습니까?"

- "Google Drive에 연결" 을 누릅니다.
- 계정 선택 창이 뜨면 1-1에서 폴더를 만든 계정을 고릅니다.
- "허용" 을 누릅니다.
- 이걸 해야 노트북이 Drive에 체크포인트를 저장할 수 있습니다.

패키지 설치 로그가 한참 올라감

- `pip install ultralytics` 가 도는 중입니다. 1~2분 걸립니다.

그러면 학습이 시작되고 이런 줄이 에폭마다 올라옵니다.

```
  [sync] epoch 3 -> Drive   (세션 경과 0.02h)
```

이 줄이 나오면 Drive 저장이 되고 있는 겁니다. Drive에 가서
`drone_hackathon/runs/R9_yolo11n_1280x736_selftest/weights/` 를 열어보면
`last.pt` 파일이 실제로 생겨 있습니다.

### 1-5. 일부러 끊고 다시 실행 (이 단계가 핵심입니다)

5에폭쯤 돌아간 걸 확인한 뒤, 메뉴에서 런타임 > 세션 관리 를 누릅니다.

창이 뜨면 실행 중인 세션 옆의 "종료" 를 누릅니다. 학습이 중간에 끊깁니다.
일부러 끊는 것이니 걱정하지 않아도 됩니다.

그 상태에서 다시 런타임 > 모두 실행 을 누릅니다. 설정은 아무것도 바꾸지
않습니다. Drive 연결 팝업이 다시 나오면 똑같이 허용합니다.

이 메시지가 나오면 성공입니다.

```
============================================================
이전 체크포인트 발견 — 이어서 학습합니다
============================================================
  마지막 완료 epoch: 5
```

그리고 1이 아니라 6 에폭부터 이어서 올라갑니다. 학습이 시작되기 직전에
이 줄도 같이 나와야 합니다.

```
설정 검증 통과 — CFG 그대로 적용됨
```

재개할 때 Ultralytics가 학습 설정을 기본값으로 되돌려버리는 경우가 있습니다.
mosaic이 다시 켜지고 optimizer와 학습률이 바뀌는데, 에러가 나지 않아서 그냥
넘어가면 앞부분과 뒷부분이 다른 조건으로 학습된 모델이 나옵니다. 노트북이 매번
확인해서 다르면 멈추도록 해뒀습니다. 위 줄이 안 보이면 알려주세요.

왜 이걸 굳이 하냐면, 체크포인트가 저장되는 것과 그걸로 실제 재개가 되는 건
별개의 문제이기 때문입니다. 저장은 잘 되는데 재개에서 걸리는 경우가 흔한데,
그걸 15시간짜리 본런이 9시간째 끊기고 나서 알게 되면 처음부터 다시입니다.
지금 5분 들여서 확인해두는 게 맞습니다.

만약 "신규 학습 시작" 이 나오고 1 에폭부터 시작한다면 재개가 안 되는 것입니다.
그 화면을 캡처해서 알려주세요.

확인이 끝나면 Drive의 `drone_hackathon/runs/R9_yolo11n_1280x736_selftest/`
폴더는 지워도 됩니다. 이름에 `_selftest` 가 붙어 있어서 본런과 섞이지 않습니다.

### 1-6. CU 소모량 확인

Colab 화면 오른쪽 위에 RAM/디스크 그래프가 있고, 그 옆이나 아래에 남은 컴퓨팅
단위(CU)가 표시됩니다. 자체 점검 시작 전과 끝난 뒤의 숫자를 적어두세요.

L4가 시간당 CU를 얼마나 쓰는지 알아야, 100 CU로 R9(80에폭)와 R10을 둘 다
돌릴 수 있는지 계산이 됩니다. 모자라면 에폭 수를 줄이거나 한쪽을 포기해야 하는데,
그건 미리 알아야 하는 정보입니다.

## 2단계. 데이터 도착 후

### 2-1. 데이터셋 검증

1280x736 데이터셋을 만든 뒤 반드시 아래와 대조합니다.

| Split | Images | Boxes | Negative |
|---|---:|---:|---:|
| train | 26,177 | 28,149 | 10.00% |
| val | 5,020 | 6,201 | 9.16% |
| test | 5,557 | 9,153 | 3.26% |

하나라도 다르면 split이 틀어진 것이므로 여기서 멈춥니다. 그 상태로 학습하면
R6, R8과 비교가 안 되는 숫자만 나옵니다.

### 2-2. tar로 묶어서 업로드

```bash
cd data/processed
tar -cf external_uav_phase1_v2_1280x736.tar external_uav_phase1_v2_1280x736/
```

gzip은 쓰지 마세요. 이미 JPEG이라 거의 안 줄고 압축과 해제 시간만 늘어납니다.

만든 tar를 `MyDrive/drone_hackathon/data/` 에 올립니다. 5~7GB라 시간이 걸립니다.

폴더째 올리면 안 됩니다. Drive는 작은 파일 수만 개를 다루는 게 매우 느려서,
반드시 tar 하나로 묶어야 합니다. 노트북이 이 tar를 Colab 로컬 디스크로 복사한 뒤
풀어서 씁니다. 마운트된 Drive에서 직접 학습하면 데이터 읽기에서 병목이 걸립니다.

### 2-3. 스모크 2 에폭

```python
SELFTEST = False
SMOKE    = True
```

전체 실행합니다. 확인할 것은

- tar가 복사되고 풀리는 데 걸린 시간
- `data.yaml` 이 잡히고 train / val / test 파일 수가 맞게 찍히는지
- 로그에 찍힌 자동 배치 크기 (다음 단계에서 씁니다)
- 1 에폭에 걸린 시간 (80 에폭 총 시간을 여기서 추산합니다)

### 2-4. 본런 R9

```python
SELFTEST = False
SMOKE    = False
CFG["BATCH"] = 16      # 스모크 로그에 찍힌 값으로
```

배치를 고정값으로 바꾸는 게 중요합니다. `-1`(자동)인 채로 두면 세션이 끊겼다가
다른 GPU에 재배정될 때 문제가 됩니다. 재개는 체크포인트에 저장된 배치 값을 그대로
쓰고 GPU를 다시 보지 않기 때문에, 큰 GPU에서 정해진 배치가 작은 GPU에 복원되면
OOM으로 죽습니다.

### 2-5. R10

R9가 끝난 뒤에 돌립니다. 동시에 두 개를 돌리면 CU가 두 배로 빠지고, R9 결과를 보고
R10을 조정할 여지도 없어집니다.

```python
_RUN   = "R10_yolo11n_p2_1280x736"
_MODEL = "/content/work/p2_1280x736.yaml"    # 팀원에게 받은 P2 config
```

P2 config는 Ultralytics 기본 제공이 아닙니다. 팀원이 R7, R8에 쓴 것을 받아서
Drive에 올리고 경로를 지정해야 합니다.

## 결과 확인

학습이 끝나면 Drive의 `runs/{RUN_NAME}/` 에 아래가 남습니다.

| 파일 | 내용 |
|---|---|
| `weights/last.pt` | 마지막 에폭 |
| `weights/best.pt` | Ultralytics 기준 최고 |
| `weights/best_map50.pt` | mAP50 최고 |
| `results.csv` | 에폭별 지표 |

`best.pt` 와 `best_map50.pt` 가 다를 수 있습니다. Ultralytics는 `best.pt` 를
mAP50이 아니라 `0.1 x mAP50 + 0.9 x mAP50-95` 로 고르기 때문입니다. R1에서도
mAP50 최고는 16 에폭이었는데 `best.pt` 는 14 에폭이 저장됐습니다.
mAP@0.5 0.70이 목표 지표이므로 `best_map50.pt` 를 쓰세요.

## 자주 막히는 것

| 증상 | 원인과 대응 |
|---|---|
| `Drive에 아카이브가 없습니다` | tar 업로드가 안 끝났거나 경로가 다름. `MyDrive/drone_hackathon/data/` 확인 |
| CUDA out of memory | 배치가 GPU에 비해 큼. `CFG["BATCH"]` 를 절반으로 |
| 재개했는데 1 에폭부터 시작 | `RUN_NAME` 이 바뀌었는지 확인. 이름이 다르면 다른 실험으로 봅니다 |
| GPU 사용률이 낮고 느림 | 디코딩 병목. `WORKERS` 를 올림 |
| RAM 부족으로 세션 종료 | `WORKERS` 를 4나 2로 낮춤 |
| 12시간 넘게 안 끝남 | 백그라운드 실행이 켜져 있는지 확인 |
